- **Base melhor que a do git:** `git merge-file -p --diff3 ours base theirs` com base = `git show v1.4.263:<mesmo caminho>` (nenhum dos 32 UU foi renomeado), ours = `:2:`, theirs = `:3:`. O rebrand da base/theirs vai **só em linha que não é comentário nem título `it(`/`describe(`**: o fork deixa "Orca" em comentário e em título de teste, e rebrandar tudo cria conflito falso. Script no scratch do grupo (`g1/m3.py`, `ap.py` resolve hunk por índice).
- **Arquivo em que o upstream reestruturou e o fork só enxertou** (ResolvedView, StructuredSession, ComposerPane, ComposerField, EmptyState, BackgroundTasksStatus, HelpMenu): pegue `:3:` com rebrand e reaplique o `diff base ours` à mão. Mais rápido e seguro que ler os hunks do diff3.
- **Upstream moveu o código e o fork depende dele:** o enxerto vai para o arquivo novo (`NativeChatCrewBackgroundTasksStatus.tsx`, `help-menu-controller.tsx`, `agent-message-row-lead.ts`, `native-chat-composer-field-props.ts`). Esses ficam `A` no índice e **sem rebrand**: rebrande as strings visíveis ("Restart Orca", URL do GitHub).
- **Feature do fork que o upstream refez** (P69/P70 faixa recolhida, prévia de Markdown em largura total): upstream agora tem coluna de notas (`--md-rail-width`, `is-adding-note`) e card de pergunta com colapso próprio. Fica o upstream + `BRZA-SYNC: rodada`; o código morto do fork sai (`annotationBlockClassName`).
- **Strip duplicada de nome:** o fork tem `NativeChatPromptStrip({kind,title})` e o wrapper `NativeChatCardPromptStrip({card})` para a do upstream; todo chamador novo do upstream (`NativeChatStructuredPromptCard`) usa o wrapper. `takeFocus` precisa passar pelas duas.
- **Modo Markdown da caixa:** o upstream passou a montar o schema em `nativeChatPromptExtensions()` (inclui o pill de side chat) e a posição de texto em `createPromptTextPositionTracking`. O modo plain usa o schema do upstream inteiro; o Markdown mantém o próprio mais `nativeChatPromptPills`, sem o pill de side chat. Contagem de texto do rastreio e `insertPromptMention` recebem as `coordinates` do modo.
- **max-lines conta sem branco nem comentário e o tsx limita em 400:** Session, PromptEditor e NoticeRow estouraram por 1-9 linhas; saiu para helper (`brza-divider-label.ts`, `replaceMarkdownPromptText`, `usePromptTextPositionTracking`, `useBrzaPromptSlot(sessionId, prompts)` com o `useBotLinkPrompt` dentro).
- **tsc direto no worktree** (`node_modules/.bin/tsc --noEmit -p config/tsconfig.web.json --composite false`, ~10 s) funciona quando `grep -rlE '^<<<<<<< ours' src` está vazio; filtre `test-harness|test-support|test-viewport|test-fixtures`, que são do grupo UD.
- **Dobras de API do upstream que quebram fork-only:** `resolveNativeChatHttpLinkRouting(state, worktreeId, url)` ganhou o 3º argumento; `selectClaudeProviderAccount` mudou para `runtime-provider-account-selection` (o `vi.mock` do teste também); `NativeChatRowActionsProvider['chat']` ganhou campos (use `ComponentProps<…>['chat']`); `getClaudeStatusActiveId` devolve `undefined`; o disclosure store trocou `runScroll` por `toolRunMeasurements`; `agentStatusByPaneKey` é `acceptedAgentStatuses()`.
- **Hunk que a ordem importa:** `OT` (ours depois theirs) em hunk que repete uma linha de contexto duplica a linha (`lineTitle = false,`); releia o resultado.
